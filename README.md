## 为什么做这个

聚合阅读器一般是「作者在代码里写死几十个站点的选择器」：站点一改版，用户只能等作者发版。
而漫画站改版是常态 —— 换域名、换模板、把目录塞进内联脚本，一年能变两三回。

MangaView 反过来做：**不内置任何站点**。程序在运行时去读站点，你填一个首页地址，
它自己打开首页 → 详情页 → 第一章，把列表、目录、正文三组选择器推出来，看完识别结果再保存。
规则存在一份 JSON 里，能改、能导入、能给朋友。

附带的结果是：抓取规则不在代码里，所以这个仓库里没有一行属于某个具体站点。
它是个阅读器，不是内容源。

## 它能做什么

### 添加站点：只需要一个地址

左侧抽屉 → 添加站点 → 粘贴首页地址 → 开始识别。过程逐步显示，不是转圈等：

```
· 打开首页            · 已连接（HTTPS）
· 首页识别到 59 部作品   · 搜索可用（/search?keyword={keyword}）
· 打开详情页            · 识别到 75 个章节
· 打开第一章            · 识别到 253 张图片
```

推出来的选择器会填进 JSON 输入框，看得懂就改，看不懂就保存。首页整屏由脚本渲染、
抓不到列表但搜索好用的站，降级成**仅搜索**配置 —— 不会给你一份看着完整、点进去全是空的配置。

站内搜索也是探出来的，不是写死的 `?q=`：先读页面上的搜索框（`<form>` 的
`action`/`method`、输入框的 `name`），连 POST 和隐藏域一起照抄成规则；
页面上没有表单（提交逻辑写在 JS 里）才退到「试常见搜索地址」和「拿一个生僻词探一下
哪个参数真的生效」。识别报告里的「搜索：可用」后面会注明是哪一种，方便判断可信度。

### 竖向连续阅读

按屏幕宽度采样解码，长图不会一进页面就吃掉几十兆；滑到倒数第三页就预取下一章的前两页，
到末尾自动接上，翻章不白屏。返回键永远一步回到目录，不会沿着章节栈退十几层。
停稳 600 毫秒才落盘进度 —— 连续滑动不会写几百次，杀进程也不会丢最后一页。

预加载会给可见页让路：只要屏幕里还有图在加载，后面的投机预加载就停在闸门外。
带宽和解码名额优先给「正在看的那一页」，因为翻页时的等待最容易被感知。

### 看完能查的加载性能

图片链路每一段都记了账：耗时、从内存/磁盘/网络哪来、失败原因、当时的并发。
阅读页不显示这些 —— 每秒刷一次数字除了耗电，还会影响滚动本身 ——
从抽屉或阅读页菜单进「图片加载统计」才看得到：

```
96.8%   加载成功率      320ms   平均耗时
78%     缓存命中率      2       当前并发
```

再往下是 p50 / p90、可见页与预加载各自的平均耗时、命中构成、并发峰值、
失败归因（超时 / 防盗链 / 断流）、最近失败的样本、磁盘缓存占用与清理入口。
统计只存在内存里，重启清零；取消的请求不计入成功率 —— 滑动时取消预加载是正常行为，
算进去只会让数字随滑动变低，看起来像网络坏了。

### 换源

目录页或阅读页随时换到另一个站点：用书名去目标站搜索，结果按标题相关度排序；
从阅读页发起时还会抓一次对方目录，**按章号对上同一话就直接读那话**，并且停在原来的位置。
搜索阶段不切换全局站点 —— 只是「看一眼有没有」，不该影响首页。

### 进度与历史

一条记录就是一本漫画的完整状态：书名、封面、详情页、来源站点、章节、页码。
历史里能续读、能「搜同书」换个源接着看、能单条删除。

### 配置可移植

粘贴 JSON（自动剥掉 markdown 代码围栏）、选文件、从链接导入，也可以把当前能用的配置导出给别人。
保存前有个**试抓首页**按钮：用未保存的配置真跑一次，显示解析到几部作品加前三条标题。
这是判断一份配置能不能用的唯一可靠方式。

## 自动识别和「在代码里写死选择器」的区别

写死选择器的识别器只能回答「这个选择器对不对」，回答不了「这个站该用哪个选择器」。
首页上热门、最新、推荐、广告四组板块结构几乎一样（图片 + 链接 + 文字），先出现的那个纯属排版顺序。

**先列候选，再打分。** 候选生成（`ListCandidates`）不做任何取舍，把可能成列表的节点集合全列出来，
包括「全站封面图」这种没有统一容器的形态。评分（`ListScorer`）用**运行时的同一个解析器**真解析一遍，
再把事实交给算术：

| 分量 | 含义 | 首页权重 | 章节权重 |
| --- | --- | --- | --- |
| N | 条目数量（对数饱和，30 条封顶） | 0.20 | 0.30 |
| I | 图片有效率 | 0.25 | — |
| T | 标题有效率 | 0.25 | 0.30 |
| U | 地址有效率 | 0.20 | 0.25 |
| D | DOM 结构一致性 | 0.10 | 0.15 |

叠加惩罚项：结构不一致、标题/地址重复、封面指向图标广告、落在导航页脚里、选择器过宽、
章节名不像章节。30 部完整作品会稳定赢过 5 条没有标题的广告位。

**结构一致性专治「过宽的选择器」。** 每个条目算一份「标签名@深度」的结构签名（不掺 class，
避免 `odd` / `first` 这类可变名干扰），用序列编辑距离比相似度，阈值 0.8 —— 真实模板常在某些条目上
多一个「NEW」角标，全等比较会把它当成另一种结构。`div.grid > div` 同时框进作品卡和横幅时条数很好看，
但一致性只有 0.5，会被这条压下去。

**语义特征补上 class 读不懂的那一大片。** 真实站点里 `item-123`、`box-a1` 很常见，但语义没消失，
它散在 `alt="封面"`、`itemprop=name`、链接文字「第 12 话」、URL 路径 `/promo/8` 里。
用法刻意保守：**正向只做小幅偏向，负向才是硬否定** —— 容器叫 `book-list` 加 0.02，
容器叫 `promo-banner` 扣 0.15。因为语义判断本身会错（广告位完全可以叫 `book-item`），
而「名字里写着 promo」几乎没有反例。

**图片地址：`src` 只是候选之一。** 同一张封面可能出现在七个地方，而 `src` 常常是占位图。
地址解析独立成 `ImageUrlResolver`，按可靠性给候选打分：`data-original` 100 → `data-src` 95 →
`srcset` 85 → `src` 80 → 背景图 75；占位图（`data:`、`blank.gif`、1×1）直接判 0 分。
`srcset` 取最大的一档 —— 真实站点常把「小图预览 + 原图」写在一起。

**置信度记录的是已经发生的事实。** 解析出多少条、多少条标题非空、第一章是否真打开过，
不做基于页面猜测的加分。结果随配置一起保存，以后排查「这份配置当时怎么来的」不用靠记忆：

```json
"confidence": { "overall": 0.984, "home": 1, "detail": 1, "reader": 0.955 }
```

完整推导、权重、已经处理过的近 20 种站点形态，写在 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 它不做什么

- **不提供、不托管、不分发任何漫画内容**，仓库里没有站点规则，只放一份格式模板。
- **不绕过人机验证、登录墙、加密接口**。整屏 JS 渲染且搜索也不可用、正文由加密接口下发、
  必须登录才能看 —— 直接报错并说明原因，不硬生成一份假配置。
- **证书错误不自动放宽**。握手失败是确定性结论，停下来弹窗给你看证书详情，
  只有点了「仍然关闭证书校验」才会带上例外重新识别，配置里会写明风险。
- **明文 HTTP 必须有配置授权**。没有授权的 `http://` 在发请求前就被拦下，
  报「已阻止不安全的明文连接」，而不是含糊的「网络异常」。

## 隐私

- **不需要账号**，没有埋点、没有广告 SDK、没有崩溃上报 —— 依赖清单里只有 Compose、
  Navigation、DataStore、Coil、jsoup。
- **站点配置、阅读进度、浏览历史都只存在这台手机**（`filesDir/sources` 与 DataStore）。
- **唯一的网络请求是你配置的站点**：抓列表、目录、正文图片。图片按站点要求带 Referer，
  不额外上传任何东西。
- 装完是空的，没有任何预置站点。

## 开始使用

**自己编译**：

```bash
./gradlew :app:assembleDebug      # 产物 app/build/outputs/apk/debug/app-debug.apk（约 15MB）
./gradlew :app:testDebugUnitTest  # 234 个单元测试，默认不联网
```

需要 JDK 17 以上与 Android SDK 37；minSdk 24，Android 7.0 起能装。
工具链的坑（AGP 9 不再需要 Kotlin 插件、`compileSdkMinor`、块注释可嵌套）写在
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)。

装好之后：左侧抽屉 → 添加站点 → 填首页地址 → 开始识别 → 保存，回到首页就是这个站的排行榜。

## 技术栈

| 层 | 选型 |
| --- | --- |
| UI | Jetpack Compose + Material 3，Navigation Compose |
| 抓取 | jsoup 1.17.2 解析，`HttpURLConnection` 发请求（严格 TLS + 明文闸门） |
| 图片 | Coil 2.6 + 自定义 `PageBoundsDecoder`：按屏采样、2 的幂对齐、像素预算 |
| 存储 | DataStore Preferences 存设置与历史，站点配置是 `filesDir/sources/*.json` |
| 识别 | 纯 JVM 启发式，无 Android 依赖，能在单测里离线跑完整流程 |
| 构建 | AGP 9.5 / Kotlin 2.4.21 / Gradle 9.8.2，手写依赖容器，无 DI 框架 |
| 测试 | 234 个单测 · 19 组离线夹具 · 9 组带标准答案的语料 |

三个引擎（源适配 / 阅读 / 自动识别）的边界、图片链路的取舍、连接安全的判定表，
都在 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。
